# AGENTS.md — aws-samples

Repository-specific instructions, on top of the global rules (`~/AGENTS.md` and
`~/workspace/config/ai/rules/`). This is the only instruction file of the repo: no `CLAUDE.md`
or `GEMINI.md`. Skills are global (`task skills` in the config repo), never versioned here.

## Stack

Terraform samples for AWS, one stack per `samples/<name>/infra/`. `samples/base` (VPC, endpoints, KMS key, AWS Config)
is applied first; the other samples read its outputs through `terraform_remote_state`.

| Sample | Shape |
|---|---|
| `base` | VPC, VPC endpoints, the shared KMS key, ECR Public pull through cache, AWS Config |
| `rds-aurora-pg` | Aurora PostgreSQL Serverless v2 (+ Node.js IAM-auth Lambda sample in `app/`) |
| `ecs-service` | ECS cluster and Fargate service |
| `ecs-task` | ECS task definition run as a batch |
| `msk-akhq` | MSK cluster and the AKHQ UI on ECS behind an ALB |
| `lambda-s3` | S3 notification to a Python Lambda (asynchronous retries, SQS DLQ) |
| `lambda-kinesis` | Kinesis stream to a Python Lambda (partial batch retries, idempotent DynamoDB writes, SQS DLQ) |
| `step-function-s3` | Two Step Functions started by S3 through EventBridge: a Distributed Map of Lambdas, an ECS job |
| `ecs-task-s3` | ECS task run by an EventBridge rule on S3 events (delivery retry, SQS DLQ) |

## Tests

- `terraform test` only, one `tests/floci.tftest.hcl` per stack: it applies the stack on the Floci emulator with
  fake credentials (`task <sample>:test`, `task test-all`). Never `plan`/`apply` against the real provider in a test.
- The image is pinned once, in the root `Taskfile.yml` (`FLOCI_IMAGE`), read by the CI and kept by Renovate.
- Emulator gaps are handled in the test (`override_resource`, `override_data`, `override_module`, each with the reason
  as a comment), never by changing the stack. The outputs of `base` are replaced by the default network of Floci.
- The event-driven samples (`lambda-s3`, `lambda-kinesis`, `step-function-s3`, `ecs-task-s3`) add a `run "e2e"` to
  that file: the helper module `infra/tests/e2e` drops files or records, waits for the results (and for the failure
  records of the DLQ) and reads the contract back from Floci. `aws` CLI only inside test helpers, forced to the Floci
  endpoint with fake credentials (`tests/e2e/floci-aws.sh`).
- Python Lambda code: `task <sample>:app-test` (ruff, pyright, offline pytest, tools pinned in `requirements-dev.txt`,
  configured in the root `pyproject.toml`). `task <sample>:e2e` is a smoke test on the real account, for the user only.

## Commands

Task is the only entry point: `task --list`.

```bash
task setup                 # tools, git hooks, TFLint plugins
task test-all              # terraform test of every stack on Floci
task review                # pre-commit, KICS, Trivy
task <sample>:init|plan|apply|destroy|docs|test
task <sample>:app-test      # Python samples: ruff, pyright, pytest
task <sample>:e2e           # smoke test on the real account (user only)
```

## Rules for this repo

- No `plan`/`apply`/`destroy` and no `aws` command from an agent (`aws` CLI only inside test helpers, forced to the
  Floci endpoint with fake credentials): the `<sample>:*` tasks that reach an account (`init`, `plan`, `apply`,
  `destroy`, `e2e`) and `bootstrap:s3` are for the user (use `task --dry`).
- CI never holds cloud credentials and never plans, applies or deploys. GitHub Actions (`.github/workflows`) is the
  only CI: there is no GitLab mirror.
- The state bucket is never written in code: `TF_VAR_state_bucket` in `.env` (git-ignored, see `.env.example`) feeds
  `-backend-config` and the `state_bucket` variable. Backends use native S3 locking (`use_lockfile`).
- One customer managed KMS key for all the samples, created in `base` (`kms_key_arn` output): every stack encrypts
  with it (logs, databases, streams, queues, buckets...) and never creates a key of its own.
- Terraform, providers and modules are pinned exactly (lock files are git-ignored). Every variable has a `validation`.
  A module is the last release that accepts the pinned aws provider, and the Lambda runtime is the newest the provider
  accepts (Python 3.13: the provider validates the runtime name).
- Security findings: fix, else ignore inline next to the resource with the reason. Never a global ignore or a lower
  `fail-on`.
- `TFDOCS.md` is generated by pre-commit, never edited.
- `CHANGELOG-IA.md`: one `## [YYYY-MM-DD] - Daily Log - ...` entry per day.
