# AGENTS.md — aws-samples

Repository-specific instructions, on top of the global rules (`~/AGENTS.md` and
`~/workspace/config/ai/rules/`). This is the only instruction file of the repo: no `CLAUDE.md`
or `GEMINI.md`. Skills are global (`task skills` in the config repo), never versioned here.

## Stack

Terraform samples for AWS, one stack per `samples/<name>/infra/`. `samples/base` (VPC, endpoints, AWS Config) is
applied first; the other samples read its outputs through `terraform_remote_state`.

| Sample | Shape |
|---|---|
| `base` | VPC, VPC endpoints, AWS Config |
| `rds-aurora-pg` | Aurora PostgreSQL Serverless v2 (+ Node.js IAM-auth Lambda sample in `app/`) |
| `ecs-service` | ECS cluster and Fargate service |
| `ecs-task` | ECS task definition run as a batch |
| `msk-akhq` | MSK cluster and the AKHQ UI on ECS behind an ALB |

## Tests

- `terraform test` only, one `tests/floci.tftest.hcl` per stack: it applies the stack on the Floci emulator with
  fake credentials (`task <sample>:test`, `task test-all`). Never `plan`/`apply` against the real provider in a test.
- The image is pinned once, in the root `Taskfile.yml` (`FLOCI_IMAGE`), read by the CI and kept by Renovate.
- Emulator gaps are handled in the test (`override_resource`, `override_data`, `override_module`, each with the reason
  as a comment), never by changing the stack. The outputs of `base` are replaced by the default network of Floci.

## Commands

Task is the only entry point: `task --list`.

```bash
task setup                 # tools, git hooks, TFLint plugins
task test-all              # terraform test of every stack on Floci
task review                # pre-commit, KICS, Trivy
task <sample>:init|plan|apply|destroy|docs
```

## Rules for this repo

- No `plan`/`apply`/`destroy` and no `aws` command from an agent: the `<sample>:*` tasks and `bootstrap:s3` are for the
  user (use `task --dry`).
- CI never holds cloud credentials and never plans, applies or deploys. GitHub Actions
  (`.github/workflows`) and GitLab CI (`.gitlab-ci.yml`) stay in sync, except `terraform test` on Floci (GitHub only).
- The state bucket is never written in code: `TF_VAR_state_bucket` in `.env` (git-ignored, see `.env.example`) feeds
  `-backend-config` and the `state_bucket` variable. Backends use native S3 locking (`use_lockfile`).
- Terraform, providers and modules are pinned exactly (lock files are git-ignored). Every variable has a `validation`.
- Security findings: fix, else ignore inline next to the resource with the reason. Never a global ignore or a lower
  `fail-on`.
- `TFDOCS.md` is generated by pre-commit, never edited.
- `SPECS.md`: one `## [YYYY-MM-DD] - Daily Log - ...` entry per day.
